# troy-mode-trial 规则

## 1. 规则类型

- **硬规则**：不满足就不能合入。
- **软规则**：PR 描述里写明原因就可以合入。
- **审查**：由某个角色检查。
- **流程**：由 troy-mode 自己遵守。

## 2. 规则

| 编号 | 规则 | 类型 | 由什么保证 | 适用范围 | 起始日期 |
| --- | --- | --- | --- | --- | --- |
| R01 | 每个 PR 只有一个 commit，且它的标题行等于 PR 标题。审查后的修改通过修改那个 commit 完成，或者用 squash 合并。 | 硬 | CI | troy-mode | 2026-11-07 |
| R02 | 每个 PR 只包含一个阶段的产出：文档、源码或测试之一。 | 硬 | CI | troy-mode | 2026-11-07 |
| R03 | 源码 PR 最多改动 500 行（新增加删除，不算锁文件和自动生成的文件），最多涉及 5 个文件。测试 PR 不限。只拆分文件的 PR 可以超限，但要写明。 | 软 | CI | troy-mode | 2026-11-07 |
| R04 | 函数体最多 50 行，不算注释、文档注释和空行。复杂的对外接口调用多个功能单一的内部函数。 | 硬 | Lint | troy-mode | 2026-11-07 |
| R05 | 文档注释使用 Google 风格。代码注释只用英文。 | 硬 | Lint | troy-mode | 2026-11-07 |
| R06 | 源码文件最多 500 行（总行数，含注释）。超过就拆分文件。 | 软 | Lint | troy-mode | 2026-11-07 |
| R07 | 模块之间只能按架构允许的方向依赖，只通过对外接口调用，不能有循环。 | 硬 | 依赖检查工具 | troy-mode | 2026-11-07 |
| R08 | 开发工程师永远不改测试文件。 | 硬 | Hook 和 CI | troy-mode | 2026-11-07 |
| R09 | 测试 PR 里的每个新测试对着 mock 都失败。 | 硬 | CI | troy-mode | 2026-11-07 |
| R10 | 每个测试都标上它的用例编号或 bug 编号：测试自己的名字以编号开头，例如 `test_f04_t07_writes_header`。尚未验收的功能、尚未修复的 bug，它们的测试失败记为预期失败。其余测试必须通过。 | 硬 | 测试运行器配置和 CI | troy-mode | 2026-11-07 |
| R11 | 实现 PR 中，改动代码的行覆盖率不低于 90%，分支覆盖率不低于 80%。95% 是目标，不是门槛。排除的代码行必须写明原因，并经测试经理批准。 | 硬 | CI | troy-mode | 2026-11-07 |
| R12 | 英文文档是事实来源。改英文文档的 PR 必须同时更新中文镜像。中文镜像的文档头注明它对应的英文版本。 | 硬 | CI | troy-mode | 2026-11-07 |
| R13 | 状态标签要如实说明功能做到哪一步，比如"在 main 上通过测试"和"在 Troy 的设备上可用"要区分开。 | 审查 | 产品经理 | troy-mode | 2026-11-07 |
| R14 | 只有带性能指标的接口才写性能测试。在固定的机器上运行，留出余量，和上一次的基线比较。 | 审查 | 测试经理 | troy-mode | 2026-11-07 |
| R15 | 每个修过的 bug 都保留它的重现测试。 | 审查 | 测试经理 | troy-mode | 2026-11-07 |
| R16 | 引入新的第三方依赖需要架构师批准。 | 审查 | 架构师。CI 会标出所有依赖文件的改动。 | troy-mode | 2026-11-07 |
| R17 | 审查循环最多 3 轮，之后升级上报。 | 流程 | troy-mode | troy-mode | 2026-11-07 |
| R18 | 前 3 个功能的 PR 1 和 PR 2 由 Troy 合并。其他 PR 在检查和审查都通过后由 Claude 合并。什么时候全部交给 Claude 合并，由 Troy 决定。 | 流程 | troy-mode | troy-mode | 2026-11-07 |
| R19 | commit 使用 Troy 全局 CLAUDE.md 里规定的邮箱。commit 信息、PR 标题和 PR 描述不带任何 Claude 署名，也完全不提 Claude 或 Anthropic，除非 `.troy-mode/config.toml` 把署名检查模式设为 `trailers`。 | 硬 | Hook 和 CI | troy-mode | 2026-11-07 |
| R20 | 合并的文档和 PR 描述里没有模板标记或填写说明。 | 硬 | CI | troy-mode | 2026-11-07 |
| R21 | 每个改动都通过从单独分支发起的 PR 进入 `main`。永远不要在 `main` 上提交、推送 `main`，或从 `main` 开 PR。 | 硬 | Hook 和 CI | troy-mode | 2026-11-07 |
| P01 | 异常信息不能在 raise 里直接写成 f-string。先把信息赋给变量，例如 msg = f"..."，再 raise ValueError(msg)。 | 硬 | Lint（ruff EM102） | project | 2026-11-08 |
| P02 | 已于 2026-11-08 停用。每条错误信息都要写出它说的是哪个文件。库直接抛出的 Python 自带异常也算在内：如果 Python 的信息里没有文件名，就捕获该异常，用同一类型重新抛出，并在信息里写上文件路径。与任何文件无关的错误不受此限，例如路径参数类型不对。 | 审查 | 无 | project | 2026-11-08 |
