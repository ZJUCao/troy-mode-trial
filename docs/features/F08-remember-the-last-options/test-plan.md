# F08 Remember the last options: test plan

## 1. Feature

- ID and name: F08 Remember the last options
- Design: [design.md](design.md)

## 2. Cases

F08 adds the settings file and the external interfaces of settings, and changes `main` and `wordcount`. The cases reach each interface the way its caller does.

- **settings.** F08-T01 to F08-T25 import `OPTION_NAMES`, `settings_path`, `settings_name`, `load_option`, and `save_option` as `from troy_mode_trial.settings import ...`, as design section 2 says. They pass `load_option` and `save_option` a `pathlib.Path` in the test's `tmp_path`.
- **`main`.** F08-T26 to F08-T43 call it in the test's own process, as `from troy_mode_trial.cli import main`. They read standard output and standard error with pytest's `capsys`, and make the test's `tmp_path` the working directory with `monkeypatch.chdir`, unless a case says otherwise. Through `capsys` a line break is `\n` on both systems.
- **`wordcount`.** F08-T44 to F08-T48 start the installed program as a new process, as F07's plan does: no shell, the working directory set to `tmp_path`, standard output and standard error captured as bytes, and the program found with `shutil.which("wordcount", path=sysconfig.get_path("scripts"))`. If the program is not there, the test fails. It never skips. The process inherits the test's environment, so it uses the data folder below. In these cases `<NL>` is `os.linesep` as bytes. The program must be installed again once F08's code lands (design section 3.1, item 6). An install from before F08 makes these cases fail, and they never skip.

**The data folder.** No test reads or writes Troy's real data folder (architecture section 10, design section 3.3, item 4). This PR adds two automatic fixtures, one in `tests/conftest.py` and one in `version-tests/conftest.py`. For every test, each makes a new empty folder with `tmp_path_factory`, so the folder is never inside the test's `tmp_path`, and sets both `APPDATA` and `XDG_DATA_HOME` to its absolute path with `monkeypatch.setenv`. This plan calls that folder the data folder. A test may ask the fixture for it. "The settings file" is `<data folder>/wordcount/settings.json`, and `<S>` is `str()` of that path, built by the test with `pathlib.Path`, so it uses `\` on Windows. The tests of F04 to F07 that check that a run writes no file scan only `tmp_path`, so they keep passing unchanged (section 4). A case that changes `APPDATA`, `XDG_DATA_HOME`, or `HOME` does so with `monkeypatch`, and a case that unsets `XDG_DATA_HOME` on Linux also sets `HOME` to a folder of its own, so the home folder fallback never reaches the real one.

**Files.** Each test makes its own files and writes them in binary mode, as the exact bytes the case gives. `EF BB BF` names the bytes of a byte order mark, and other two-digit hexadecimal groups name single bytes. Unless a case says otherwise, these files are in `tmp_path`:

- `notes.txt` holds `Hello world\n  troy-mode  trial\n`, the prototype's file: 4 words, 2 lines, 31 characters, longest word 9.
- `greeting.txt` holds `你好 世界!\r\n`, the prototype's file: 2 words, 1 line, longest word 3.
- `latin1.txt` holds `café au lait\n` in Latin-1.
- `sub` is an empty folder.

**Saved bytes.** These are the four contents of design section 2.1, each with one `\n` at the end and no byte order mark: the null bytes `{"option": null}\n`, the lines bytes `{"option": "lines"}\n`, the chars bytes `{"option": "chars"}\n`, and the longest bytes `{"option": "longest"}\n`. "Holds the lines bytes" means the file's whole content is exactly those bytes. "Unchanged" for a file means the same bytes and the same modification time in nanoseconds. "Holds only `X`" for a folder means that `X` is its one entry, so no `settings.*.tmp` file is left.

**Usage lines.** "The F08 usage line" is exactly `usage: wordcount [--lines | --chars | --longest | --again] FILE`, design section 3.1, proposal 1, which Troy approved with the design. "Usage error" means: `main` raises `SystemExit` whose `code` is `2`, or the program exits with code 2, and standard output is empty, and standard error holds exactly two lines, the first exactly the F08 usage line and the second starting with `wordcount: error: `.

"Exactly" means the whole text, as in F04's plan. The suite runs on Windows 11 and on Linux. A case expects the same result on both, unless it names a system. A case for one system skips on the other. A Linux case that removes a right skips when the process runs as root, which has every right anyway, and restores the mode afterward.

**The usage-line cases of F05 and F07.** F05-T13, F05-T14, F05-T15, and F05-T23 check the first line of a usage error word for word, as the F07 line `usage: wordcount [--lines | --chars | --longest] FILE`, and so do F07-T30, F07-T31, F07-T32, and F07-T36. F08 changes that line (design section 3.3, items 1 and 2). F05 and F07 are accepted, so these eight cases must pass in every F08 PR, before and after F08's code (R10), and the implementation PR may not change tests (R08). This PR therefore changes F05's plan to version 0.3 and F07's plan to version 1.1. In both, the expected usage line gains a state: the F08 usage line once F08's code is on the branch under test, and the F07 line while it is not. Each case finds the state through the interface it tests, with a probe whose output it throws away:

- `main(["--again", "notes.txt"])` returns `0` or `2` without raising once F08's code has landed. While it has not, it raises `SystemExit` with code `2`, and the second line of standard error is exactly `wordcount: error: unrecognized arguments: --again`.
- `wordcount --again notes.txt` exits with code 0, or with code 2 and standard error exactly one line that starts with `wordcount: no saved options to run again: `, once F08's code has landed. While it has not, it exits with code 2 and the second line of standard error is exactly `wordcount: error: unrecognized arguments: --again`.

Any other outcome of the probe fails the case, so no case accepts either line. `--again` changes none of their second lines. The eight cases keep their names and change nothing else. No case of F04 to F07 is retired: F06-T28 and F06-T34 check the line against a pattern that the F08 usage line matches, and the other usage errors of F04 and F06, and v0.2-S16 in `version-tests/test_v0_2_scenarios.py`, check only how the line starts (design section 3.3, item 3). `version-tests/test_v0_2_scenarios.py` keeps its tests as they are, and its runs of `wordcount` use the data folder of the new fixture in `version-tests/conftest.py`.

**Against the mock.** This assumes that the mock PR adds `src/troy_mode_trial/settings.py` with `OPTION_NAMES` as design section 2.2 gives it and with the four functions, each with a body that raises `NotImplementedError`, and leaves `main` and its usage line exactly as they are on `main`. Then each settings case gets `NotImplementedError` instead of its result or its exception. F08-T01 checks `OPTION_NAMES` together with `save_option` and `load_option`, so it fails too. Each `main` and `wordcount` case with `--again` gets a usage error for an unrecognized `--again`, or the F07 usage line instead of the F08 line. Each case without `--again` checks a saved file, a warning, or a later `--again` run, which the mock does not give (R09). The eight F05 and F07 cases pass against the mock, because their probe finds that F08's code has not landed. If the mock's `main` already accepts `--again`, the probe would get `NotImplementedError`, and those cases would fail, which R10 does not accept, so the Test Engineer reports it before the test PR.
