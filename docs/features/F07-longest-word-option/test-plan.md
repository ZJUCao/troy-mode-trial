# F07 Longest word option: test plan

## 1. Feature

- ID and name: F07 Longest word option
- Design: [design.md](design.md)

## 2. Cases

F07 has three external interfaces, and the cases reach each one the way its caller does.

- **`count_longest`.** F07-T01 to F07-T19 import it as a caller does, `from troy_mode_trial import count_longest`.
- **`main`.** F07-T20 to F07-T33 call it in the test's own process, as `from troy_mode_trial.cli import main`. They read standard output and standard error with pytest's `capsys`, and make the test's `tmp_path` the working directory with `monkeypatch.chdir`, unless a case says otherwise. Through `capsys` a line break is `\n` on both systems.
- **`wordcount`.** F07-T34 to F07-T37 start the installed program as a new process, as F04's plan does: no shell, the working directory set to `tmp_path`, standard output and standard error captured as bytes, and the program found with `shutil.which("wordcount", path=sysconfig.get_path("scripts"))`. If the program is not there, the test fails. It never skips. In these cases `<NL>` is `os.linesep` as bytes.

Each test makes its own files in `tmp_path` and writes them in binary mode, as the exact bytes the case gives, so that `\r\n` reaches the program unchanged. In the inputs, `\xXX`, `\uXXXX`, and `\UXXXXXXXX` name one Unicode code point, which the test encodes as UTF-8, and `EF BB BF` names the bytes of a byte order mark. Unless a case says otherwise, these files have this content:

- `notes.txt` holds `Hello world\n  troy-mode  trial\n`, the design's example: 4 words, the longest `troy-mode`, 9 characters.
- `windows.txt` holds `EF BB BF` followed by `Hello world\r\n  troy-mode  trial\r\n`, as Notepad saves it: longest word 9.
- `greeting.txt` holds `你好 世界!\r\n`, the design's example: 2 words, the longest `世界!`, 3 characters and 7 bytes.
- `dashes.txt` holds `-- ...\n`, the design's example: no word.
- `latin1.txt` holds `café au lait\n` in Latin-1, so its bytes start `63 61 66 E9 20`.
- `sub` is an empty folder.

Characters outside ASCII in a file's name are UTF-8. The suite runs on Windows 11 and on Linux. A case expects the same result on both, unless it names a system.

"Exactly" means the whole text, as in F04's plan. "The F07 usage line" is exactly `usage: wordcount [--lines | --chars | --longest] FILE`, the line of design section 2.1, which Troy approved with the design. "Usage error" means: `main` raises `SystemExit` whose `code` is `2`, or the program exits with code 2, and standard output is empty, and standard error holds exactly two lines, the first exactly the F07 usage line and the second starting with `wordcount: error: `. F05 and F06 are accepted and their code is on `main`, so the usage line no longer depends on a landing order, and every F07 case checks it word for word.

**F05's usage-line cases.** F05-T13, F05-T14, F05-T15, and F05-T23 check the first line of a usage error word for word, as `usage: wordcount [--lines | --chars] FILE`. F07 changes that line (design section 3, item 2). F05 is accepted, so these four cases must pass in every F07 PR, before and after F07's code (R10), and the implementation PR may not change tests (R08). This PR therefore changes F05's plan to version 0.2: its `<USAGE>` gains a third state, `usage: wordcount [--lines | --chars | --longest] FILE`, once F07's code is on the branch under test. Each of the four cases finds that state the way it already finds F06's, through the interface it tests: `main(["--longest", "notes.txt"])` returns `0` once F07's code has landed and raises `SystemExit` with code `2` while it has not, and `wordcount --longest notes.txt` exits with code 0 or 2 in the same way. Any other outcome of that probe fails the case. Their second lines do not change, because `--longest` changes none of their messages. F07's test PR makes this change in `tests/test_cli_lines.py`, for example with a second constant next to `USAGE_BOTH` and a second probe, rather than replacing `USAGE_BOTH`. The four cases keep their names. F06-T28 and F06-T34 check the usage line against a pattern that the F07 usage line matches, F06's other usage errors check only that the first line holds `--chars`, and F04's cases check only that it starts with `usage: wordcount `, so their plans do not change.

Against the mock, every case fails because the option is not implemented. This assumes that the mock PR adds `count_longest` with a body that raises `NotImplementedError` before it looks at `path`, exports it from `troy_mode_trial`, and leaves `main` and its usage line exactly as they are on `main`. Then each `count_longest` case gets `NotImplementedError` instead of its result or its exception. Each `main` case gets a usage error that does not know `--longest`, or the old usage line `usage: wordcount [--lines | --chars] FILE` instead of the F07 usage line. Each `wordcount` case gets exit code 2 and that usage error instead of its output (R09). F05's four cases pass against the mock, because their probe finds that F07's code has not landed. If the mock already accepts `--longest` in `main`, the probe of F05's cases would get `NotImplementedError` and F05's tests would fail, which R10 does not accept, so the Test Engineer reports it before the test PR.

## 3. Performance cases

None. Design sections 2.1, 2.2, and 2.3 set no performance target, and requirements 7.1 sets none for the project (R14).
