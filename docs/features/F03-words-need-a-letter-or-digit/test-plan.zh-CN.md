# F03 词须含字母或数字：测试方案

## 1. 功能

- 编号和名称：F03 词须含字母或数字
- 设计：[design.zh-CN.md](design.zh-CN.md)

## 2. 用例

F03 不新增接口。每个用例都像调用方一样调用 F01 的 `count_words`：`from troy_mode_trial import count_words`。每个测试在 pytest 的 `tmp_path` 里自建文件，并以二进制方式写入用例给出的确切字节，这样 Windows 不会把 `\n` 改成 `\r\n`。输入中的 `\uXXXX` 和 `\UXXXXXXXX` 表示一个 Unicode 字符，测试把它编码为 UTF-8。测试套件在 Windows 11 和 Linux 上运行，每个用例在两个平台上预期相同的结果。

“F01 结果”指在实现 F03 之前，`count_words` 按 F01 的词定义返回的值。每个用例的每个输入在 F03 下的结果都与之不同，所以无论测试工程师如何把用例拆成测试，每个 F03 测试都会在当前代码上失败（R09）。

| 编号 | 层级 | 接口 | 测什么 | 准备和输入 | 预期结果 |
| --- | --- | --- | --- | --- | --- |
| F03-T01 | 功能 | `count_words` | 设计中的示例：不含字母或数字的串（`--`、`...`、`_`）不是词，含字母或数字的串（`don't`、`x--y`、`3.14`）各算一个词。 | `dashes.txt` 内容为 `Wait -- what ... don't x--y 3.14 _`。以 `str` 形式传入其路径调用 `count_words`。F01 结果：`8`。 | 返回 `5`，且结果的类型恰好是 `int`。 |
| F03-T02 | 功能 | `count_words` | 设计中的第二个示例：只含不带字母或数字的串的文件返回 0。 | `only-symbols.txt` 内容为 `-- ... !!!`。F01 结果：`3`。 | 返回 `0`。 |
| F03-T03 | 单元 | `count_words` | 一串不含字母或数字的 ASCII 标点或符号不是词。下划线既不算字母也不算数字。 | 六个文件：`--`、`...`、`_`、`!@#$%^&*()`、`"'` 和 `+-*/=<>`。F01 结果：每个都是 `1`。 | 每个都返回 `0`。 |
| F03-T04 | 单元 | `count_words` | 不含字母或数字的串分布在多行、被多种空白隔开时，结果仍是 0。 | `--\r\n...\n\t_ \v!!!\f`。F01 结果：`4`。 | 返回 `0`。 |
| F03-T05 | 单元 | `count_words` | 含至少一个字母或数字的串算一次，不论字母或数字在串中的位置，也不论串中还有什么。 | `don't x--y 3.14 --a-- !1! _x --`。F01 结果：`7`。 | 返回 `6`。只有最后的 `--` 不算。 |
| F03-T06 | 单元 | `count_words` | 含非 ASCII 字母的词仍各算一次，单独的表情符号不是词。替代 F01-T09。 | `café naïve 日本語 \U0001F600 Ελληνικά`（第四串是表情符号 U+1F600）。F01 结果：`5`。 | 返回 `4`。 |
| F03-T07 | 单元 | `count_words` | 不含字母或数字的 Unicode 符号和标点串不是词。 | `\U0001F600 — «» € © → 。、 …`（表情符号、长破折号、书名号式引号 « »、欧元符号、版权符号、右箭头、中文句号和顿号、省略号）。F01 结果：`8`。 | 返回 `0`。 |
| F03-T08 | 单元 | `count_words` | “字母或数字”指 `str.isalnum()`：包括非 ASCII 的数字和数码，以及不是十进制数字的数值字符。 | `² ½ Ⅻ ٣ ß -- …`（上标二、二分之一、罗马数字十二、阿拉伯-印度数字三、德语 ß、两个连字符、省略号）。F01 结果：`7`。 | 返回 `5`。 |
| F03-T09 | 单元 | `count_words` | 出现在第一个字符以外位置的 U+FEFF 不是空白。只由它组成的串不是词，它与字母同在的串是一个词。替代 F01-T11。 | 三个文件：`a ﻿ b`；字节 `EF BB BF EF BB BF`（开头有两个标记，别无其他）；`a﻿b ﻿`。F01 结果：依次为 `3`、`1` 和 `2`。 | 依次返回 `2`、`0` 和 `1`。 |
| F03-T10 | 单元 | `count_words` | 在大文件中计数仍然正确，此时不含字母或数字的串，或唯一的字母或数字位于一端的串，可能跨越任何内部读取边界。 | 一个文件：100,000 个 `-` 后接 `x`，一个空格，100,000 个 `.`，一个换行符，`7` 后接 100,000 个 `_`，一个空格，再接 200,000 个 `ab -- `。文件大小为 1,500,005 字节，大于 1 MiB。F01 结果：`400003`。 | 返回 `200002`。 |

退役的 F01 用例：F03 改变了 F01-T09 和 F01-T11 的预期结果，F01 测试方案 1.1 把这两个用例移到其“不测的内容”一节。F03-T06 和 F03-T09 以新结果覆盖它们的输入。在 F03 的测试 PR 中，测试工程师从 `tests/test_count_words.py` 删除 `test_f01_t09_non_ascii_words` 和 `test_f01_t11_inner_bom_is_word_part`，因为 F01 已验收，它的测试必须通过（R10），而这两个测试在 F03 实现后会失败。新测试使用 F03 的用例编号，所以不再有测试叫 `test_f01_t11_inner_bom_is_word_part`，这个名字已不能描述该用例。

## 3. 性能用例

无。F03 沿用 F01 给 `count_words` 的性能指标，即无；需求 7.1 也没有给项目设任何性能指标（R14）。

## 4. 不测的内容

| 内容 | 原因 |
| --- | --- |
| F03 保持不变的 `count_words` 部分：签名、可接受的路径形式、错误、忽略文件开头的一个字节顺序标记、以空白分隔、关闭文件、不写入任何东西。 | F01-T01 到 F01-T08、F01-T10、F01-T12 到 F01-T21 以及 B13 的复现测试检查这些行为，它们在 F03 下预期结果不变。为它们新增 F03 用例会在当前代码上通过，这违反 R09。 |
| `count_words` 文档注释的文字。 | 它不是调用方通过接口能观察到的行为。设计 3.1 要求修改它，由 F03 实现 PR 的评审检查。 |
| 性能。 | 没有性能指标（R14）。 |
