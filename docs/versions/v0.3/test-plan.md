# v0.3 version test plan

## 1. Version

- Version: v0.3
- Features: F05, F06, F07, F08, F09
- Requirements: [docs/requirements.md](../../requirements.md#6-version-plan)

## 2. End-to-end scenarios

Every test makes its own files in a temporary folder. It writes each file in binary mode, as the exact bytes the scenario gives, so that Windows never turns `\n` into `\r\n`. Characters outside ASCII are encoded as UTF-8 unless the scenario gives other bytes.

The scenarios follow the `wordcount --lines FILE`, `wordcount --chars FILE`, `wordcount --longest FILE`, `wordcount --again FILE`, and `wordcount --sentences FILE` flows in requirements section 3, the F05 to F09 prototypes, the decisions Q5, Q7, Q8, and Q10 to Q26, the data model in architecture section 5, and the error handling in architecture section 6. Troy approved the designs of F05, F06, and F07, and the three features are accepted. The designs of F08 and F09 are not written yet. So the scenarios rely only on what the requirements, the prototypes, architecture 4.0, and the approved designs of F04 to F07 already fix:

- A file error prints one line `wordcount: <FILE>: <reason>` to standard error and exits with code 2 (ADR-0002). Q8 and the requirements of F06 to F09 say that each option gives the same message and exit code as `wordcount FILE`. So for a file that is not valid UTF-8, a scenario compares the option's output with the output of `wordcount FILE` for the same file, instead of fixing a reason text.
- A wrong command line exits with code 2, leaves standard output empty, and writes a usage line to standard error. The F07 design fixes the usage line `usage: wordcount [--lines | --chars | --longest] FILE`, and the F08 and F09 designs may change it to show `--again` and `--sentences`. So a scenario checks only that standard error starts with `usage:`.
- A settings error on `--again` and the settings warning each write one line that names the settings file (requirements Q20 and Q22, architecture section 6). The F08 prototype shows a settings error, but it leaves the exact text to F08's design. So a scenario checks that standard error is exactly one line that holds the absolute path of the settings file, or, in a PowerShell session, that it holds `settings.json`.
- The settings file is UTF-8 JSON: one object with exactly one key, whose value is `null` for a run with no counting option or the name of the run's option (architecture section 5). F08's design fixes the key and the names. So v0.3-S35 checks the shape of the file and not its key or names, and v0.3-S32 writes only content that breaks the shape whatever key F08's design picks.

The scenarios run the installed command, as Troy does. The release test runs in the conda environment `troy-mode-trial` with the project installed, so `wordcount.exe` is in the environment's scripts folder and on `PATH`. If no `wordcount` is on `PATH`, the test fails. It never skips.

No scenario of Claude's reads or writes Troy's real data folder (architecture section 10). The automatic fixture in `version-tests/conftest.py` sets `APPDATA` and `XDG_DATA_HOME` for every test to a new empty folder outside the files' folder. This plan calls that folder the data folder. Every `wordcount` and `powershell.exe` process that a test starts inherits both variables, so the settings file is `<data folder>\wordcount\settings.json`. This plan calls that path the settings file. A scenario that needs a second data folder says so.

- v0.3-S01 to v0.3-S14, v0.3-S17 to v0.3-S24, v0.3-S26 to v0.3-S37, and v0.3-S39 to v0.3-S47 start the `wordcount` that is on `PATH`, the program that PowerShell starts for `wordcount`, as a new process with the scenario's arguments. Each test captures standard output, standard error, and the exit code.
- v0.3-S15, v0.3-S25, v0.3-S38, and v0.3-S48 run the commands in Windows PowerShell, `powershell.exe -NoProfile -NonInteractive -Command`, to check that PowerShell finds the command with each option and that `$LASTEXITCODE` holds its exit code.

When a scenario compares output, it reads `\r\n` as `\n`. "One line break" means one `\n` or one `\r\n` at the end. Unless a scenario says otherwise, the working directory is the files' folder.

### 2.1 Count lines in PowerShell (F05)

v0.3-S01 to v0.3-S06 run `wordcount --lines`. The command counts lines as F02 counts them: `\n`, `\r\n`, and `\r` each end one line, a last line without a line break still counts, and an empty file has 0 lines (Q2, Q3).

### 2.2 Count characters in PowerShell (F06)

v0.3-S07 to v0.3-S12 run `wordcount --chars`. A character is one Unicode code point of the decoded text, line ends included. `\r\n` is two characters, and the command translates no line end (Q11). One byte order mark at the start of the file is not counted (Q12).

### 2.3 Wrong command lines and PowerShell (F05 to F09)

v0.3-S13 and v0.3-S14 check the command lines that requirements section 8 and the decisions Q7, Q10, and Q13 rule out. v0.3-S15 runs `--lines` and `--chars` in PowerShell, as Troy does. Troy runs v0.3-S16 by hand, with all five options.

### 2.4 Find the longest word in PowerShell (F07)

v0.3-S17 to v0.3-S25 run `wordcount --longest`. A word is what F03 counts as a word: the whole run of characters that are not white space, if it holds at least one letter or digit. Punctuation that touches a word belongs to it (Q15). The length is the number of Unicode code points, as for `--chars`. One byte order mark at the start of the file is not part of a word (Q5). A file with no word prints 0. v0.3-S24 checks the command lines that requirements section 8 and the decisions Q14 and Q16 rule out.

### 2.5 Run again with the last option in PowerShell (F08)

v0.3-S26 to v0.3-S38 run `wordcount --again`. Every run that prints a count keeps its option, or that it had none, in the settings file, and `--again FILE` counts FILE with that option (Q17, Q18). A run that fails, by a file error or a wrong command line, leaves the settings file as it was (Q19). `--again` with no saved option, or with a settings file it cannot read, is a settings error with exit code 2 (Q20). `--again` together with a counting option is a wrong command line (Q21). When the settings file cannot be written, the count still prints with exit code 0, and a warning goes to standard error (Q22). In each scenario, "the files of v0.3-S27" are `notes.txt` as in v0.3-S01 and `greeting.txt` as in v0.3-S27, in the working directory.

### 2.6 Count sentences in PowerShell (F09)

v0.3-S39 to v0.3-S48 run `wordcount --sentences`. A sentence is a run of text that ends in a run of `.`, `!`, or `?`, and that holds at least one letter or digit, a character for which `str.isalnum()` is true (Q23, Q24). Text after the last mark is not a sentence (Q25). A mark ends a sentence wherever it stands, also inside a number. A line break ends no sentence, and the Chinese marks `。`, `！`, and `？` end none either (Q26). One byte order mark at the start of the file is ignored (Q5). v0.3-S46 checks the command lines that requirements section 8 and the decision Q13 rule out. v0.3-S47 checks that `--again` keeps `--sentences` too (requirements section 5).

The counts in v0.3-S22 and v0.3-S23 fail if the command breaks one rule of section 2.4:

- `punct.txt` prints `6` for `don't,`. Without its comma the word would have 5 characters.
- `combining.txt` prints `5` for `café` written as five code points. Joined into one `é`, the word would have 4.
- `mixed.txt` prints `5` for `don't`. U+3000 separates `日本語` from `テキスト`, and `_` and `😀` hold no letter or digit, so neither is a word.
- `breaks.txt` prints `5` for `three`. A lone `\r` is white space, so `one` and `two` are two words.
- `bom-word.txt` prints `9` for `troy-mode`. With the byte order mark, the word would have 10 characters.

The counts in v0.3-S44 and v0.3-S45 fail if the command breaks one rule of section 2.6:

- `runs.txt` prints `3`, because a run of marks such as `?!` or `!?!` ends one sentence (Q23). A mark for each sentence would give `8`.
- `lines.txt` prints `1`, because a line break ends no sentence. `Wait` and `OK` end in no mark.
- `chinese.txt` prints `0`, because `。`, `！`, and `？` end no sentence (Q26). Counting them would give `3`.
- `mixed-marks.txt` prints `1` for the one `!`. Counting `。` would give `2`.
- `no-alnum.txt` prints `2` for `Hi.` and `Bye.`. The runs `...` and `-- ?!` hold no letter or digit (Q24). Counting them would give `4`.
- `breaks.txt` prints `3`, because `four` ends in no mark (Q25). Counting it would give `4`.
- `mixed.txt` prints `2` for `Wait -- what ...` and `don't x--y 3.`, because the point inside `3.14` ends a sentence. The text after it ends in no mark.

In v0.3-S32, the text `{}` has no key, and the text `{"a": null, "b": null}` has two. The texts `{"option": 5}` and `{"option": "again"}` have one key, but `5` is not a string and `again` is not a counting option. So each of them breaks the shape of architecture section 5, whatever key F08's design picks.

v0.3-S34 and v0.3-S46 run `-a` and `-s`. Requirements section 8 rules out every option other than `--lines`, `--chars`, `--longest`, `--sentences`, and `--again`, so the command has no short form of `--again` or `--sentences`.

No scenario runs on Linux, although requirements section 7 promises the same counts on Windows 11 and on Linux. Claude's scenarios run only in the release test on Troy's PC, which runs Windows 11, and no Linux device of Troy's is on record. v0.3-S05, v0.3-S06, v0.3-S12, v0.3-S23, and v0.3-S45 count files with Linux line breaks on Windows instead. The feature tests of F05, F06, and F07 run on Linux in CI, and so will the feature tests of F08 and F09.

For the same reason, no scenario checks where the settings file is on Linux: `$XDG_DATA_HOME/wordcount/settings.json`, or `~/.local/share/wordcount/settings.json` when `XDG_DATA_HOME` is not set (Q17). On Troy's PC the command uses `APPDATA` only, and v0.3-S35 checks that it ignores `XDG_DATA_HOME` there. F08's feature tests check the Linux paths in CI.

No scenario runs with `APPDATA` unset. Architecture section 6 makes it a settings error, but no requirement or approved design fixes what the error or warning then says, because there is no settings file to name. F08's design decides it, and its feature tests check what it decides.

v0.3-S15, v0.3-S25, v0.3-S38, and v0.3-S48 use Windows PowerShell 5.1, `powershell.exe`, because every Windows 11 has it. No scenario runs PowerShell 7, `pwsh`. Both shells start the same `wordcount.exe`, so every other scenario of Claude's holds for either.
